topic: UX design for nearform_todo_app — minimal single-user personal Todo web app with a three.js floating-in-space backdrop
updated: 2026-07-23T09:58

- (event) Headless/fast-path Create run. Sources: PRD (final), PRD addendum, product brief — inherited by reference.
- (decision) Form-factor: single-surface responsive web (~320px phone to desktop). No UI system inherited; from-scratch visual identity in React+Vite. The todo LIST is the first and only screen — no login/onboarding.
- (decision) IA: one screen. Zones top-to-bottom: header/title, always-visible add-input, list of Todos (newest-first), footer bar with completed count + Clear completed. three.js Backdrop behind everything as a fixed decorative layer.
- (decision) Completed vs active visual distinction: checkbox checked + strikethrough + reduced opacity/de-emphasized ink. Completing restyles IN PLACE, never reorders (per FR-5).
- (decision) Optimistic UI for all writes (add/toggle/delete/clear): reflect within ~100ms, reconcile with server, roll back + surface inline error on failure (FR-7).
- (decision) Clear-completed guard RECOMMENDATION: undo toast (transient), not a confirmation dialog. Rationale: keeps the fast single-screen loop frictionless, matches optimistic-UI posture, reversible without a modal interrupt. Flagged as open question for human to confirm since PRD out-of-scopes delete-undo (FR-3) — clear-completed undo is a scoped exception limited to the bulk action's toast window.
- (decision) Backdrop a11y treatment: fixed layer BEHIND content; readability via a semi-opaque contrast scrim/panel behind the list so Todo text meets WCAG AA over the animated field; focus rings and text never rely on the backdrop for contrast. prefers-reduced-motion => static starfield (no animation). No WebGL => static/plain CSS gradient background. Zero critical WCAG AA violations with backdrop active (SM-4).
- (decision) Three required states designed: empty ('Nothing to do — add something above'), loading (skeleton rows + calm backdrop), error (inline non-blocking message + retry for list load; per-item rollback for action failures). App never shows a dead spinner or blank void.
- (decision) Visual identity: dark cosmic surface (deep space navy/black) so the floating-in-space metaphor is native; the list floats on a raised translucent panel. Single cool accent for primary action + focus. Aesthetic = calm, quiet, restraint — delight from the backdrop, not from chrome.
- (assumption) Dark-only visual identity; no light theme in v1 (space metaphor is intrinsically dark).
- (assumption) Add-input autofocus on desktop only, not on touch (avoids mobile keyboard pop-up on open).
- (assumption) Clear-completed server commit model (immediate+compensate vs deferred-until-toast-dismiss) deferred to architecture; both satisfy the UX.
- (event) Headless fast-path: creative tools off, reviewer gate not run (opt-in/costly, no caller signal). No key-screen mocks; app builds from spine tables.
- (event) spines finalized
- (decision) OQ-1 RESOLVED by human: clear-completed uses an Undo toast, bulk-only (~6s window); single-item delete stays undo-less per PRD FR-3. Undo affordance scoped strictly to the bulk clear action.
- (decision) Human confirmed: dark-only visual identity for v1 (no light theme). Other assumptions accepted: desktop-only add-input autofocus; evergreen browser support; clear-completed server-commit model deferred to architecture.
