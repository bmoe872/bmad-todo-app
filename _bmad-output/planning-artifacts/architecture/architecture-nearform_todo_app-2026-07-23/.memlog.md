- (decision) AD-1 Three-tier server-authoritative state. Binds: all. Prevents: divergent client state stores / direct DB access / side-channels. Rule: Postgres via the REST API is the sole source of truth; the client cache is derivative; every mutation flows through the API then reconciles.
- (decision) AD-2 Layered backend with repository chokepoint. Binds: backend. Prevents: SQL in routers, scattered business rules, no single place for owner-scoping. Rule: routes -> services -> repository -> DB, dependencies point down only; SQLAlchemy confined to repository layer.
- (decision) AD-3 Todo is the only entity; canonical shape. Binds: all. Prevents: features inventing different field names/date formats/ordering. Rule: {id:uuid, description:string, completed:bool, created_at:ISO8601 UTC Z}; List ordered created_at DESC, id tiebreak; completion never reorders.
- (decision) AD-4 REST contract on versionless base /api. Binds: frontend+backend. Prevents: divergent endpoint shapes/status codes. Rule: GET /api/todos, POST /api/todos(201), PATCH /api/todos/{id}, DELETE /api/todos/{id}(204), DELETE /api/todos/completed(200), GET /api/health; static /completed route registered before /{id}; {id} typed UUID.
- (decision) AD-5 Uniform JSON error envelope + validation. Binds: all writes/reads. Prevents: per-endpoint error shapes, XSS. Rule: errors are {error:{code,message,details?}}; description required, trimmed non-empty, single-line, <=500 chars, validated server-side and mirrored client-side; Todo text rendered as text only (React auto-escape).
- (decision) AD-6 Optimistic mutation via TanStack Query with mandatory rollback+reconcile. Binds: frontend. Prevents: ad-hoc optimistic paths that never roll back, hanging spinners. Rule: onMutate snapshots+optimistically updates cache; onError rolls back to snapshot + shows non-blocking inline error; onSettled invalidates to reconcile to server truth.
- (decision) AD-7 Clear-completed = DEFERRED bulk-delete of an explicit id snapshot (CHOSEN over immediate-delete-with-compensating-recreate). Binds: FR-9 clear-completed. Prevents: id churn/timestamp loss from re-create, deleting items completed during the undo window, true data loss on crash mid-window. Rule: on Clear completed the client captures the set of completed Todo ids, hides them optimistically, shows the ~6s Undo toast; Undo cancels the pending timer with NO server call; on toast dismiss the client issues one DELETE /api/todos/completed carrying exactly that id snapshot; server deletes only ids that are still completed. Crash during window = nothing deleted server-side yet = items simply reappear on reload (safe failure).
- (decision) AD-8 Backdrop is a fully isolated decorative layer. Binds: FR-8, NFR-Perf, NFR-A11y. Prevents: three.js blocking first paint/input, per-frame React re-renders of the core UI, backdrop breaking a11y or perf. Rule: fixed full-viewport aria-hidden pointer-events:none layer below the panel; three.js code-split and mounted AFTER the loop is interactive; owns its canvas imperatively in an effect with its own rAF loop outside React render; reduced-motion -> single static frame, no WebGL -> CSS gradient fallback, frame-budget watchdog steps down DPR/cube-count then falls back to static; pauses on tab hidden; reads no Todo data; wrapped in an error boundary that falls back to static gradient.
- (decision) AD-9 Auth/multi-user seam left open, not built. Binds: data model + API edge + repository. Prevents: building auth now AND a design that forces a rewrite later. Rule: no owner column and no auth in v1; future owner-scoping is (a) an additive Alembic migration adding owner_id+users, (b) a filter applied at the single repository chokepoint, (c) optional auth middleware at the /api edge; the Todo wire contract stays unchanged. [ASSUMPTION] no always-null owner column added in v1 (YAGNI); addendum offered it as an example only.
- (decision) AD-10 Single-origin delivery. Binds: delivery+frontend+backend. Prevents: divergent origin/CORS assumptions between dev and prod. Rule: in the composed stack nginx serves the SPA and reverse-proxies /api/* to the backend (same origin, no CORS); CORS is enabled only in the dev profile via CORS_ORIGINS env when Vite dev server (5173) calls the backend (8000).
- (decision) AD-11 Startup & durability ordering. Binds: delivery/backend/db. Prevents: app serving before schema exists; data loss on restart. Rule: Postgres data on a named volume; backend depends_on db healthy (pg_isready); backend entrypoint runs 'alembic upgrade head' before launching uvicorn; migrations are additive/non-destructive.
- (decision) AD-12 Backend runs sync SQLAlchemy 2.0 + psycopg3; FastAPI runs sync path operations in its threadpool. Binds: backend. Prevents: mixing sync/async DB access patterns across endpoints. Rule: one session-per-request via FastAPI dependency; no async DB layer in v1 (documented option, not built) given single-user scale.
